Vreau să construim backend-ul pentru o aplicație numită provizoriu “BreakOps”.

Context produs:
BreakOps este o aplicație cross-platform pentru developeri / oameni din IT care îi ajută să își gestioneze micro-pauzele, recuperarea, mood-ul, focusul și scorul zilnic de recovery.

Aplicația are:
- autentificare user
- onboarding
- profil personal
- preferințe de lucru
- mood/status pe zi sau interval orar
- plan zilnic de pauze
- break-uri programate
- status break: pending / done / skipped / snoozed / missed
- daily recovery score
- istoric ultimele 7 zile
- statistici săptămânale
- light/dark/system theme salvat în profil/settings

Stack backend:
- Supabase Auth
- Supabase PostgreSQL
- Supabase Row Level Security
- Supabase auto-generated API
- Supabase Edge Functions doar dacă sunt recomandate, dar pentru MVP prefer cât mai multă logică simplă în app
- Nu folosim service_role key în frontend
- Frontend-ul va folosi doar anon public key + RLS
- App-ul este făcut în Expo React Native + Web

Vreau să generezi tot ce ține de backend/API/DB pentru MVP:
1. schema SQL completă

Cerințe SQL:
Generează un script SQL complet pentru Supabase care include:
- enable extension pgcrypto dacă este nevoie pentru gen_random_uuid()
- create tables
- check constraints
- indexes
- updated_at trigger function
- triggers pentru updated_at
- enable row level security pentru toate tabelele private
- policies pentru:
  - userul poate selecta doar propriile rows
  - userul poate insert doar propriile rows
  - userul poate update doar propriile rows
  - userul poate delete doar propriile rows, unde are sens
- break_types trebuie să fie read-only pentru useri:
  - toți userii autentificați pot selecta break_types active
  - userii normali nu pot insert/update/delete break_types
- seed data pentru break_types cu minim 10 pauze:

  4. Posture Reset
  5. Breathing Reset
  6. Walk Break
  7. Shutdown Ritual
  8. After Meeting Reset
  9. Debugging Frustration Reset
  10. Deep Work Recovery

RLS:
Fii foarte atent la securitate.
Nu permite userului să vadă sau să modifice datele altui user.
Folosește auth.uid() în policies.

Daily plan generation rules:
- Light intensity = 3 pauze / zi
- Normal intensity = 5 pauze / zi
- Aggressive intensity = 7 pauze / zi
- Pauzele trebuie distribuite între work_start_time și work_end_time
- Pauzele trebuie să includă focus_areas din profil
- day_mode influențează tipurile de pauze:
  - deep_work: eyes, posture, mental_energy
  - coding_intense: eyes, wrists, posture
  - meeting_heavy: breathing, movement, mental_energy
  - learning_day: eyes, posture, breathing
  - low_energy: breathing, movement, shutdown
  - debugging_day: mental_energy, breathing, movement
  - launch_day: breathing, posture, shutdown
- Dacă mood_entries include dont_disturb sau deep_work pe un interval, pauzele din acel interval trebuie mutate după interval sau marcate ca silent în app
- Pentru MVP, daily_breaks nu trebuie să aibă silent flag dacă nu este necesar, dar poți recomanda dacă ar fi util

Daily recovery score:
Propune o formulă simplă:
- completed / total = până la 80 puncte
- bonus până la 20 puncte:
  - +5 pentru shutdown ritual completat
  - +5 pentru cel puțin 3 categorii diferite completate
  - +5 dacă nu există missed breaks
  - +5 dacă userul a completat minim o pauză pentru focus area principală
- scorul trebuie să fie între 0 și 100
