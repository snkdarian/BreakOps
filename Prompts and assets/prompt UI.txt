UI / DESIGN ADDENDUM PENTRU BREAKOPS

Pe lângă specificația funcțională deja definită pentru BreakOps, vreau ca aplicația să aibă un design foarte apropiat de imaginile atașate.

Imaginile atașate sunt referința principală pentru:
- dark futuristic style
- neon blue / cyan / violet accents
- cards cu glow
- sidebar web
- dashboard web
- break library web
- profile/settings web
- mobile dashboard
- mobile break library
- mobile profile/settings

IMPORTANT:
Nu vreau un UI doar vag inspirat. Vreau ca rezultatul să fie cât mai asemănător vizual cu imaginile atașate, adaptat în cod production-ready.

Design direction:
- dark mode first
- futuristic cyber/productivity dashboard
- deep navy / black gradient background
- electric blue, cyan, violet, purple accents
- rounded cards
- luminous borders
- subtle glassmorphism
- glowing progress rings
- glowing active states
- soft shadows
- modern SaaS/productivity dashboard feel
- premium app feel
- clean typography
- responsive web + mobile

Background:
- folosește dark navy / near-black, nu negru simplu
- adaugă gradient subtil radial sau linear
- poate exista un grid/noise subtil în fundal pe web
- web-ul trebuie să pară un dashboard premium, nu o aplicație mobilă întinsă

Cards:
- cardurile trebuie să aibă:
  - background dark translucent
  - border subtil cyan/blue/violet
  - radius mare: 20–28px
  - glow subtil pe hover/active
  - padding generos
  - shadow/elevation modern
- cardurile principale pot avea border glow mai puternic

Buttons:
- primary button: gradient blue → violet
- secondary button: dark background + border luminos
- active state cu glow
- hover state pe web
- pressed state pe mobile
- disabled/loading states obligatorii

Typography:
- folosește Inter / Manrope / SF Pro-like
- headings bold, mari
- labels mici, semi-bold
- body text clar
- muted text gri-albăstrui
- accent text cyan/violet

Design tokens:
Creează tokens centralizate pentru:
- colors
- gradients
- spacing
- radius
- shadows/glows
- typography
- borders
- chart colors

Nu hardcoda culori în fiecare componentă.

Responsive behavior:
Mobile:
- bottom tab navigation
- layout pe o singură coloană
- carduri stacked
- dashboard compact
- break library ca list/cards verticale
- profile/settings stacked

Tablet:
- 2 coloane unde are sens
- sidebar collapsible sau top/bottom navigation adaptiv

Web/Desktop:
- sidebar fix în stânga
- top bar
- main content grid
- right insights panel
- charts mai mari
- break library în grid 2–3 coloane
- settings în layout pe coloane

Implementation instructions:
- First implement design system and layout shell.
- Then implement Web Dashboard.
- Then implement Break Library web.
- Then implement Profile/Settings web.
- Then implement mobile equivalents.
- Use mock data only in a separate file:
  - mock/breaks.ts
  - mock/dashboard.ts
  - mock/stats.ts
- Do not hardcode mock data directly inside UI components.
- Later this data will be replaced by Supabase services/hooks.

Quality:
- TypeScript strict
- responsive
- reusable components
- no huge files
- no inline random colors
- no business logic inside UI components
- loading/error/empty states
- clean scalable code

Goal:
The result should look like a polished BreakOps product, very close to the attached dark neon screenshots, while still being implemented as production-ready responsive UI.
